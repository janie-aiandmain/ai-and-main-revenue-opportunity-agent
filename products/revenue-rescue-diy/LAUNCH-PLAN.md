## Work that removes the blocker

The new portable shadow profile removes hardcoded vendor IDs from its installation
path without broadening the demo. It proves preparation/routing/isolation locally.
The remaining connector block is removed by executing the account-specific exit
tests and releasing that adapter, not by erasing a guard or treating documentation
as certification. No production claim transfers from synthetic approval.

For a working nontechnical DIY product, the principal implementation is **secure
guided connection and provisioning**, followed by context intake and connector
verification. A source ZIP plus Cloudflare instructions would not meet this goal.
If AI & MAIN staff must manually administer every installation, describe it as a
guided service and decide its support/price separately; do not label it self-setup.

## Account dependencies, when implementation reaches them

- HubSpot: a separately authorized non-production account and labeled test record,
  permitted existing credentials or an approved app connection, and an external
  operator login. No new key/scopes should be requested merely because the current
  Codex environment lacks a credential. No real customer records are needed.
- Jobber and GoHighLevel: the owner's chosen developer/app connection model,
  account/plan API eligibility and designated test data. API contract and minimum
  permissions must be verified before designing a write adapter. No platform scopes
  are asserted based on guesswork. Required vendor hosts are not presently in
  this Codex environment's allowlist, so remote documentation/API validation is
  unavailable here until that access is configured.
- Hosted no-code connection: an approved hosting/provisioning and OAuth app
  arrangement. Single-tenant per client remains the present architecture; do not
  silently switch to shared multi-tenant data or new user management.

## Bounded next cycle

Complete one adapter and one ordinary owner journey before widening the release.
Use existing engine/review/recovery tests unchanged. Add only tests for changed
adapter/setup behavior. Reuse captures unless reasoning output generation changes;
reserve fresh calls only for a finite stated purpose. Batch the owner's required
decisions once, keep original evidence, and report executed versus pending gates.
An honest calendar completion estimate for all three connectors requires vendor
access and the app/provisioning choice; it cannot be inferred from the HubSpot
demo's test count. Do not promise that the three-platform package can launch today.
